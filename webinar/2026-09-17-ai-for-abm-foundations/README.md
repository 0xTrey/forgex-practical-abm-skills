## Session promise

The public title and promise are already in market. The webinar must cover:

- what MCP is and how it connects AI tools to real systems;
- how stronger prompts improve quality and consistency;
- where agents fit in an ABM workflow;
- why a central, versioned company brain matters;
- how a team can build and share a prompt and skill library;
- what a fresh Claude workspace looks like when grounded in a real ABM use case.

The maturity ladder is the organizing spine that connects those topics.

## Central narrative

Most marketers do not need to jump straight to autonomous agents. They need to move up one useful level.

The path is:

```text
ask a question
    ↓
direct a task
    ↓
ground the work in a company brain
    ↓
package the process as a reusable skill
    ↓
run the proven process on a trigger or schedule
    ↓
give a governed agent a goal
```

Each level adds technology, marketer behavior, underlying assets, and governance. The audience should see the same ABM job at all six levels, with the actual input, output, and layer added each time.

## Three ideas that should survive

1. **Move up one level, not five.** Most attendees will get the highest near-term value by moving from Level 2 to 3 or Level 3 to 4.
2. **The durable asset is not the model.** Brand, messaging, ICP, personas, products, proof, skills, templates, tests, and decision history should remain portable across Claude, ChatGPT, Gemini, Cursor, or a future employer's approved system.
3. **Know the plumbing.** A capable AI marketer can connect context, process, tools, permissions, and review gates. Company-provided fixtures help, but the practitioner should understand the system well enough to adapt it.

## Presenter guardrails

- Keep the public title unchanged.
- Explain the category in a model-portable way. Claude is the implementation environment, not the entire story.
- Do not attempt a live authorization flow for a consequential connector.
- Use only the fictional North Peak and Alder materials.
- Do not expose hidden model reasoning. Ask for plans, evidence, decisions, and evaluation that the audience can inspect.
- Do not call a fixed automation an agent.
- Present external community skills as attributed, locally evaluated design references for draft-only or proposed-pilot use, not as ForgeX-authored, ForgeX-certified, production-adopted, or production-proven.
- Do not install or run external community skills in the live build. Keep the demonstration on North Peak context, the safety contract, ABM Strategist, and the approval-ready Alder brief, then explain Level 4 without activating it.
- Do not imply that portable career assets include taking confidential company information. Carry methods and blank templates, not employer intellectual property.
- Do not publish, send, spend, or write to a system of record during the demonstration.

## Audience outcome

An attendee should leave able to:

1. identify their current AI for ABM level;
2. name the one layer required to move up;
3. distinguish a prompt, context corpus, skill, automation, MCP connection, and agent;
4. use the North Peak example and ForgeX skills as implementation references;
5. choose one 30-day upgrade project.
