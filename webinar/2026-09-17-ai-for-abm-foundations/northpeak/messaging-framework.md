# North Peak AI Security messaging framework

## Positioning

For enterprise teams expanding the use of models and agents across complex environments, North Peak AI Security provides one operating view for discovery, protection, and continuous monitoring. It connects AI workloads to their data, identities, infrastructure, owners, controls, and evidence so teams can move faster without separating security from the work.

## Category point of view

AI security is not a review after deployment. Security context should travel with every consequential AI decision.

Teams struggle when models, agents, data connections, identities, and infrastructure are managed as separate inventories. North Peak connects those elements into one control and evidence model.

## Message hierarchy

### Problem

AI programs move across cloud, edge, applications, data, and third parties faster than traditional review processes can track them.

### Point of view

The operating context for each AI decision should include the workload, data, identity, policy, owner, exception, and response path.

### Value

North Peak helps security, infrastructure, application, and risk teams work from one shared view while keeping delivery moving.

### Product story

1. **Discover:** map models, agents, data, identities, infrastructure, owners, and dependencies.
2. **Protect:** apply policy and control decisions in the workflow.
3. **Monitor:** preserve events, exceptions, outcomes, and evidence for continuous review and response.

### Next step

Choose one consequential AI workload. Map its dependencies, owners, policies, response path, and evidence requirements.

## Audience messages

| Audience | Lead message | Proof needed |
|---|---|---|
| CISO or Head of AI Security | Put security context into the AI decision, not after it | Control coverage, ownership, exceptions, auditability |
| VP Infrastructure and Operations | Standardize protection across plant, edge, cloud, and central operations without losing uptime | Dependency mapping, response coordination, operational continuity |
| Application and AI platform leader | Give builders a clear path from approved architecture to runtime control | Integration model, developer workflow, policy clarity |
| Risk, privacy, and compliance | Keep decisions and evidence review-ready | Decision records, source history, ownership, retention |

## Objections and responses

**"We already have cloud and security tools."**

North Peak does not replace every existing control. It connects AI-specific workloads, identities, policies, ownership, and evidence across the systems already in use.

**"We cannot add another review bottleneck."**

The goal is to move approved security context into the workflow so teams do not rebuild the review after every change.

**"Our environments are too different for one policy model."**

The control model should create a shared operating language while preserving environment-specific implementation and exceptions.

**"AI governance is owned elsewhere."**

North Peak's message should connect security, infrastructure, application, and risk ownership. It should not claim one function can govern the system alone.

## Language rules

Preferred:

- connected system
- security context
- consequential AI workload
- shared control model
- accountable owner
- response path
- review-ready evidence
- operational continuity

Avoid unless verified and narrowly qualified:

- complete visibility
- eliminate risk
- guarantee compliance
- autonomous security
- zero trust for AI
- single pane of glass
